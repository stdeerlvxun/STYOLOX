# 推理快照磁盘保护

自动推理每轮下载整份标注库输入，空队列也重复运行，旧输入缺少本地保留策略，导致 D 盘快照不断累积。本次仅修复训练端的输入快照生命周期和磁盘保护，标注服务代码不改动。

机制与限制见 [训练端快照说明](../training/SNAPSHOT_STORAGE.md)。本地新输入保留最新三份且至少十分钟，3 GiB 管理预算；磁盘保留至少 5% 或 10 GiB，下载还需两倍输入大小余量。没有新候选时延后三十分钟，模型变化提前重查。未知旧输入、历史归档、待导入输入、人工数据不自动删除。

针对本次变更的 70 项测试通过，包含真实临时 SQLite 只读处理、低空间下载拒绝、SHA 变化拒绝、路径/链接限制、保留周期、待导入保护和空队列退避。模拟测试不代表生产推理已恢复，需部署后检查真实报告及计划任务状态。

发布须先提交推送，运行 `npm run deploy:check` 确认 GitHub 分支与本地 HEAD 相等且源码干净。然后设置 `STYOLOX_RELEASE_DIR` 为发布目录，运行 `npm run release:package`，生成只含 Git 提交源码的 `styolox-latest.zip` 与 `release.json`。原包和记录按日期唯一目录保留在 `history/`；快照、权重、私有配置和图片不打包。实际训练源码以 `source-provenance.json` 的提交身份和公开仓库对应文件内容核对。
