## 此前训练实验快照

以下为本次页面发布之前的训练记录，不代表自动学习任务的实时进度。

已查明上一轮“14 个问题找回 0”指 **问题类型和框位置同时正确为 0**，
固定 0.05 下仅看位置找到 2 个。模型原有基础较弱，加上正常孔负监督过强的设计风险、
少量样本拆成 10 类，以及偏重压误报的模型选择方式，共同限制找回能力，不能简单归咎于人工标注。

本次保持筛选规则和人工数据不变，实际完成两项对照：A 限制正常区域负损失，B 再改为先找问题位置。
同一验证集、固定 0.05 下，两项都找到 **6/13 个位置**；B 的额外候选为 **14**，测试找到 **3/14、漏 11、额外候选 10**。
旧位置模型在同一测试也找到 3/14，验证找到 8/13，因此 **A/B 均未替换现有模型**。
单类“问题位置”结果不代表已预测出具体问题类型。

最新数据实验 C 已完成：**139 张、182 个确认框**，固定 0.05，只判断问题位置。
扩大后的测试集共 28 框，C **找回 15、漏 13、额外候选 54**；保留旧模型为 **找回 16、漏 12、额外候选 66**。
原 14 框困难子集从找到 3 个变为 4 个，但整体没有改善，**C 也未晋级**。
工艺孔训练区域的分数由 0.395 降到 0.170，仍高于 0.05，误报尚未解决。

本次采用保留旧权重重新生成，线上实际新增 **93 张、234 个待审核框**，另 **10 张**因有人工作业而安全跳过。
位置建议仅沿用图片原有的唯一人工问题名作为框名，**不代表模型识别出该问题类型**。
导入前后分类与人工位置摘要相等，原线上图片分类模型也保持原样。

后续每累计 **20 张有效人工确认纠错**，由本机后台进行一批训练；每 5 分钟检查一次，本机需开机登录且 GPU 可用。

- `labeler/`：分类网页、错例复核、多框补标、独立补标存储、建议推理与部署脚本。
- `training/`：图片级分类、无关图片辅助模型与 ONNX 导出，以及人工确认框的 YOLOX 数据准备、训练和待审核候选生成。

## 补标与训练规则

1. 在分类工具筛选“错例复核”或“待补标”，选择问题点并拖框。
2. 同图多个可见问题分别框选，选择正确类别；需要修正原分类时先人工修正。
3. 点击“保存补标并下一张”，自动暂存不等于人工确认。
4. YOLOX 候选必须同时满足：有已确认问题点、没有分类草稿、补标已确认且结果为 `boxed`、
   原分类指纹一致、坐标有效、原图 SHA-256 和经 EXIF 纠正后的尺寸一致。
5. 选择了正常、无关或看不清图片状态的，一律不进入问题点训练；独立无关辅助遵循单独授权规则。
6. 候选具备后，仍须按订单、售后单与重复图片进行训练/验证/测试隔离，检查类别覆盖。
   工具不会仅凭图片数量宣布可以训练。

框采用 `exif_transposed_normalized_xywh`：经 EXIF 纠正后的原图归一化坐标，非浏览器缩放坐标。
本仓库的检查工具不导出训练数据，不把任意整图或模型候选框当作人工框。

## 本地使用

当前实验使用 RTX 4060 Ti 8GB，已经完成 float32 训练；不启用混合精度。

```powershell
# 仅检查冻结的 SQLite 在线备份；不要把备份提交到仓库
python tools/audit_annotations.py --snapshot ./private/labels.sqlite3 --root ./private/images --output ./private/audit.json
python -m unittest discover -s tests -v

# 分类服务独立运行：测试目录与正式数据库分开
python -m pip install -r labeler/requirements.txt
python labeler/app.py --help
```

位置训练用法见 [training/DETECTOR_TRAINING.md](training/DETECTOR_TRAINING.md)，
图片级分类用法见 [training/README.md](training/README.md)，分类工具用法见 [labeler/README.md](labeler/README.md)。
其中带时间的指标均为历史实验；部署脚本绑定既有 101 环境，不应在其他服务器直接执行。

后续训练参照 [YOLOX 官方自定义训练说明](https://yolox.readthedocs.io/en/latest/train_custom_data.html)，
