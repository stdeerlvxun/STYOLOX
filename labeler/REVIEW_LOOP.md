# 连续审核与批次归档

本阶段是人工监督的训练闭环。机器建议始终待审核，审核后的标签与问题框才构成正式结果；不自动确认图片状态，不自动最终定责。

## 连续处理

1. 本地静默任务每 5 分钟检查 101 有效待审核框数量。少于 10 张时，使用当前保留的模型补充最多 50 张；每轮扫描推理最多 200 张，近期优先。
2. 自动补框面向当前目录的全部图片，包括未分类和已有多个问题点的图片，按近期优先分批处理。已人工确认正常／无关／看不清、已复核、已有人工框、存在未保存编辑或已有机器建议及其历史的图片跳过；换模型也不会把已审核图片重新加入。
   位置模型无法确定问题类型时显示“待选问题点”，由人选择问题和责任后才能确认。只有图片原来有唯一人工问题点时才默认带入；未审核候选不自动写入分类，也不进入训练。
3. 每批有独立编号和固定成员。进入队列后保留当前人工编辑，不因新模型出现而替换这一批。
4. 每张图片仍按 Enter 提交。整批全部完成人工审核后，冻结一份 JSON 结果并归档，包含图片相对路径、人工问题点、责任及位置框；原图不搬运或复制。
5. 归档文件存储于服务数据目录的 review-archives，由页面“审核归档”下载。归档文件写出失败时保留数据库快照并重试，不影响普通分类保存。
6. 源文件变化、未确认草稿、失效建议不算审核完成，批次会显示待处理原因；未完成批次不会被伪装成完整归档。
7. 同一模型已尝试但没有生成框的未审核图片不会每轮反复推理；模型或原图／标签变化后可重新尝试，但已审核排除规则始终优先。未识别出框不等于已人工审核或正常；当前没有新候选时明确显示等待状态，不循环生成旧任务。

## 训练与续批分开

每累计 20 张新的合规确认纠错，原有训练流程独立运行。问题模型训练筛选规则保持不变：图片状态标记排除、看不清排除、机器待审核和草稿排除。训练结果不优于当前模型时保留当前模型，续批继续使用当前模型。电脑关闭、GPU 忙或网络中断时等待并显示状态，不以此假称审核完成。

新模型晋级后只影响后续生成的批次，不重写已确认分类、已有人工框或正在审核的批次。自动续批登记支持重试，重复请求不会生成重复批次。

## 人工与机器差异如何用于训练

本次统计 147 张已审核图片：机器原始建议 313 框，人工最终保留 226 框。按位置一对一、IoU ≥ 0.5 匹配，最终框中 188 框能与原建议匹配，38 框未匹配；原建议另有 125 框无法匹配最终结果。审核动作包括删除 100 框、调整位置 26 框、新增 13 框，其中 25 框发生大幅移位。因此，38 个未匹配最终框不等于新增了 38 处问题；这些是审核样本上的差异，不能称为独立盲测准确率。

训练只在既有合规训练划分内，适度增加“人工新增漏框”和“大幅纠正位置”的样本练习：每个入选样本最多增加一次采样，即最多原来的 2 倍；全部额外采样数不超过训练集样本数的一半。原训练筛选规则继续生效，验证集与测试集的成员、权重和评估方式保持原样，不把留出样本转入训练。

明确确认的正常区域反馈继续独立保留。删除或移动机器框本身不证明旧坐标对应正常区域，也不把所有圆孔一概判为正常；工艺孔与其他结构仍以人工确认的具体区域为准。

## 何时开放自动处理

页面“审核效果”按模型和生成方式分别统计人工审核结果。只有明确提交的审核才计数，未提交、草稿和看不清不计入通过率；整图位置原样通过要求没有删除、移动或新增框。待选问题点由人工赋值另行记录，不当作模型分类正确或分类错误；已有人工标签继承也不是模型类型预测。页面显示图片和售后单覆盖、修改明细及建议门槛差距，不自动开启终判。通过率反映人审样本表现，仍需独立盲测验证漏检。

以下为本业务的建议验收目标，不是行业统一标准；本版本不据此自动开放处理权限。模型置信分数不是实际准确率，必须在未用于训练或选择模型的独立盲测集上核验。

| 开放范围 | 建议门槛 |
| --- | --- |
| 候选框辅助审核 | 位置召回率先达到 90%，再追求 95%；同时跟踪每图误框数，全部由人审核 |
| 少数成熟问题类别自动确认 | 每类 precision 至少 98%，95%置信下限至少 95%；整体问题召回至少 95%；单框正确不代表整图问题已找全 |
| 自动判无关并跳过 | 判无关 precision 的单侧95%置信下限至少 99.5%；真实问题图被误排除比例的95%上限不超过 0.5% |
| 自动判无可见问题 | 自动判正常的图片中实际有可见问题的比例，其95%上限不超过 0.1%；真实问题被判正常比例上限不超过 0.5% |

整图自动完成还必须验证“全部可见问题找全”的图片比例，不能用单框召回代替；看不清、新材料／新工艺、缺少验证样本的类别继续人工审核。责任后置，另行验证，不随问题识别一并自动完成。

按售后单、订单和近重复图片分组，隔离训练、调参验证与最终盲测；再加入后续时间段的随机生产样本。先影子运行 2–4 周，由人工核验全部拟自动处理结果。达到门槛和足够独立样本量后逐类开放，并随机抽审 10%–20%；发现重大漏判或指标下降即退回人工。

当独立抽样中完全没有错误时，单侧95%二项置信上限要低于 1%／0.5%／0.1%，仍分别至少需要 299／598／2995 次独立观察。同一订单多张相似图片不能当成同样数量的独立证据。正常及无关图片可用于独立评估，不改变问题模型的训练筛选规则。

参考：[Scikit-learn 分组验证](https://scikit-learn.org/stable/modules/cross_validation.html)、[precision/recall 定义](https://scikit-learn.org/stable/auto_examples/model_selection/plot_precision_recall.html)、[概率校准](https://scikit-learn.org/stable/modules/calibration.html)、[NIST 二项比例置信区间](https://itl.nist.gov/div898/handbook/prc/section2/prc241.htm)、[NIST 持续评估](https://airc.nist.gov/airmf-resources/airmf/5-sec-core/)。

# 自动判定与人工纠错闭环

- 待审核框由真实多类别检测器给出位置和问题类型，标准责任在确认界面带出且可改。
- 模型建议只存在建议表。人工确认才追加分类；草稿、人工框和已有分类保持保护。
- 对原空类型队列只补充未被人工触碰的建议，保留框/建议ID和坐标，同时更新未审核批次快照。源图、标签和建议指纹变化时跳过，旧页面提交要求重新读取。
- 原样确认计通过；改类型、移框、删除误报、补出漏框分别统计。只有真实模型类型参与类型正确率，人工继承标签不冒充预测。责任准确率单独待验证。
- 审核效果的“训练对比”显示同一验证集的训练前后找回、漏检、误报及整图通过率。整图通过要求一对一匹配 IoU≥0.5，所有已标注问题找回且没有多余框；类型训练另要求类型正确。历史未记录的整图率保留为空。
- 新模型的实际人工通过率需上线后积累，不能用验证成绩代替。自动终判仍关闭。
- 每20张合规确认图片触发本地静默训练。待审低于10张时补充最多50张，已经审核过的图片不会重新入队，完成批次自动归档。
- `GET /api/training-rounds/state`读取独立持久化的训练摘要；worker经原有令牌保护的`POST /api/training-rounds/record`幂等发布，不修改人工数据库。

## 纠错动作与训练含义

- 删除框、移除全部机器框只记录删除；移框、改类型或删后重画记录位置/类型/可能替换关系，均不把原区域标成正常。删除后仍可直接撤销，删空后 Enter 可确认待补真问题框。
- 图片上的编辑浮层提供“工艺孔 / 正常结构 / 其他误报”三个明确入口。只有使用这些入口并确认整图，才新增局部正常纠错区域；原有图片状态筛选规则不变。
- 新正常区域携带 `normal_provenance={source:"human_explicit_normal",action:"process_hole"|"normal_structure"|"confirmed_false_positive",confirmed:true}`。后端校验 action 与 reason 对应，反馈导出保留该字段。
- 新反馈事件保留原 kind/changes，并新增 `correction_semantics` 数组区分 `geometry`、`type`、`normal`、`replacement`、`ambiguous_delete`。重画关联仅按重叠推断（`replacement_inferred:true`），不能作为正常负例。
- 不迁移或覆写历史分类、框、历史与反馈。历史 `process_hole/normal_structure` 保留明确原因兼容；没有上述 provenance 的历史 generic `false_positive` 不补造人工确认，训练端应排除其正常负例用途。
